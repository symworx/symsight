# Security Policy

## Supported versions

Security fixes are applied on a best-effort basis to the latest release on the default branch. Pre-1.0 releases may receive fixes only on the latest tag.

| Version | Supported |
|---------|-----------|
| 0.1.x   | Yes       |
| < 0.1   | No        |

## Reporting a vulnerability

**Do not open a public GitHub issue for security-sensitive reports.**

Please report vulnerabilities privately via **GitHub Security Advisories** —
use [Report a vulnerability](https://github.com/symworx/symsight/security/advisories/new)
on this repository.

Private vulnerability reporting is the preferred channel once the repository is
public. Until a maintainer mailbox is published, there is no email fallback.

Include:

- A short description of the issue and impact
- Steps to reproduce (or a proof of concept)
- Affected version / commit if known
- Whether you plan to disclose publicly and on what timeline

We will acknowledge receipt when we can and work on a fix or mitigation. Please give a reasonable window before public disclosure.

## What is in scope

- Secrets handling in this project (e.g. accidental logging of `XAI_API_KEY`)
- Path traversal or unsafe file writes under draft/final directories when using untrusted input
- Dependency issues in first-party code that enable remote code execution or data exfiltration

## What is out of scope

- Compromise of third-party APIs (xAI / SpaceXAI) or your own API keys
- Content generated by the model (accuracy, compliance, or “advice” quality)
- Social-engineering of maintainers or users
- Denial of service against public LLM endpoints

## Secrets and local data

- Never commit `.env`, API keys, private brand YAML, or client drafts.
- Rotate any key that may have been exposed.
- Generated content under `content/` is local by default and should stay out of public forks unless intentionally published.
